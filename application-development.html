Application Development

Learn how software is planned, designed, built, tested, released, and maintained.

Subject overview

Application Development is about turning an idea into working software. You learn how teams plan, design, build, test, release, and maintain applications, and how apps store and use data.

Software Development Life Cycle (SDLC)

The SDLC is the step-by-step process teams follow to produce software. Its common phases are:

  1. Planning: decide the goals, scope, schedule, and budget.
  2. Requirements analysis: find out what users need.
  3. Design: plan screens, data, and architecture.
  4. Implementation: write the code.
  5. Testing: find and fix defects.
  6. Deployment: release to users.
  7. Maintenance: fix, update, and improve after release.

Common models

ModelHow it worksBest when
WaterfallPhases run one after another in a fixed order.Requirements are clear and stable.
AgileShort sprints deliver working software and use constant feedback.Requirements may change.
PrototypeA sample version is built early so users can react to it.Users are unsure what they want.
Remember: Waterfall is sequential. Agile is iterative. Both include the same basic activities.

Requirements gathering and analysis

A requirement is something the system must do or be. Analysts collect requirements through interviews, questionnaires, observation, and reviewing existing documents.

  • Functional requirements: features and behavior (for example, "the student can submit a quiz").
  • Non-functional requirements: qualities such as speed, security, reliability, and usability.
Example: "The system shall calculate the percentage score" is functional. "The page shall load in under 3 seconds" is non-functional.
Remember: Good requirements are clear, testable, and agreed upon by the users or client. Tools such as use case diagrams and user stories help organize them.

System design and development

Design decides how the system will be built. It includes the architecture (for example, client-server), the database design, and the screen layouts. Diagrams such as flowcharts, ER diagrams, and UML are common.

Development (implementation) is writing the code following the design, using good practices:

  • Use meaningful names and comments.
  • Split programs into small, reusable modules.
  • Use version control (such as Git) to track changes and collaborate.

User interface (UI) and user experience (UX)

  • UI is what users see and touch: buttons, menus, colors, fonts, and layout.
  • UX is how it feels to use the product from start to finish: is it easy, fast, and clear?

Designers start with wireframes (simple layout sketches), then mockups (visual designs), then prototypes (clickable versions).

Good design principles: consistency, clear feedback, simplicity, accessibility (readable text, good contrast), and responsiveness on different screen sizes.

Software testing and debugging

Testing checks whether the software works as expected. Debugging is finding and fixing the cause of a defect.

Level or typeWhat it checks
Unit testingSingle functions or methods in isolation
Integration testingModules working together
System testingThe whole application against the requirements
User acceptance testing (UAT)Real users or the client confirm it meets their needs
Black-box testingInputs and outputs only, without looking at the code
White-box testingInternal code paths and logic
Types of errors: syntax errors (the code breaks language rules), runtime errors (crash while running), and logic errors (runs but gives wrong results).

Application deployment and maintenance

Deployment makes the finished application available to users, for example by uploading a website to a server or publishing an app to an app store.

Maintenance keeps the software useful after release:

  • Corrective: fix bugs found by users.
  • Adaptive: change the software for new platforms or rules.
  • Perfective: improve features and performance.
  • Preventive: clean up code to avoid future problems.

Database integration and application functionality

Most applications store data in a database. The app sends queries and shows the results to the user.

  • CRUD: Create, Read, Update, Delete are the four basic operations.
  • Primary key: a unique identifier for each row.
  • Foreign key: a field that links to the primary key of another table.
  • Validation: check user input before saving it.
SELECT name, grade FROM students WHERE grade >= 75;
INSERT INTO students (name, grade) VALUES ('Ana', 90);
UPDATE students SET grade = 92 WHERE id = 1;
DELETE FROM students WHERE id = 1;
Remember: Never build SQL by joining user input directly into the text. Use prepared (parameterized) statements to prevent SQL injection.
